# A② 公開を前提にしたカードの防御試験

## 設計判断

- 攻撃者は公開されたサーバー・クライアントのコードと ACAR v1 の通信仕様を読めます。自分の席のトークンと公開証明書を持ち、正規クライアントを使わずに任意の要求を TLS 内で送れると仮定します。
- カードの正本はサーバーに置き、TLS 接続に結びつけた席と手番、通し番号、対局のリビジョンを検査します。クライアントへ返す個別の札 ID は受信者自身のものに限定します。
- 既存の権威サーバーを独立した Python クライアントで検査します。Python 側で既存のゲームクライアントの制限に頼らず、公開仕様からフレームを組み立てます。テストの判定役のみ全席のテスト用返信を参照し、改変フレームは認証済みの一つの接続へ送ります。

## 再現手順

Windows の公開チェックアウトで実行します。C++ Player のビルドや GPU、実運用の鍵は不要です。

```powershell
cargo build --manifest-path server_rs/Cargo.toml --release --locked
cargo test --manifest-path server_rs/Cargo.toml --release --locked
python -B tools/card_client_probe/test_open_security.py
```

| 試験 | 観測する結果 |
| --- | --- |
| 有効なカード取得と4席分の返信 | 正常な取得を1回成立させ、対になる札の除去も含め、各席に期待される札を計算します。復号した返信を読み、各席の公開枚数と、自分の札 ID・未使用領域のゼロ埋めを照合します。 |
| 認証済みクライアントから偽の勝敗を送信 | サーバー返信を模したフレームを送っても接続を閉じます。再認証後は切断・再接続に伴うリビジョンだけが変化し、有効なカード取得は引き続き成立します。 |
| 再接続をまたいだ取得操作の再送 | 元の要求と、リビジョンだけ現行値に変えた要求は拒否されます。新番号・旧リビジョンも拒否され、仕様上消費される当事者の操作番号を除き、全席向けの返信が変化しません。 |

判定は標準出力と CI のジョブ結果を参照します。試験プロセスはループバックだけを使い、毎回新しい証明書と認証ファイルを `output/card-authority-tests/` 以下に作ります。ログを外部へ共有するときは、鍵、トークン、全席分の生データを除きます。

この試験は単一の信頼済みサーバーと認証済みクライアントの境界が対象です。管理者権限でのサーバー侵害、認証情報の窃取、端末間の共謀、通信時刻などの副経路、別物理 PC、FPS の可視性、公式配布物の署名検証は別の実証範囲です。公開レビューでは上記の入力、判定理由、実行結果を確認できます。

## 実行結果（2026-11-18）

標準Windows Actionsの公開チェックアウト \`a7108089\` でRustサーバーをReleaseビルド。既存のRust単体試験6本と、TLS上で実サーバーに接続した公開プロトコル向け追加試験3本が成功した。対象は今回の脅威モデルに含めた他席情報の非配信、再接続をまたぐ操作再送、認証済みクライアントによる偽の勝敗通知。 [標準Actionsの結果](https://github.com/Qutalize/Noctis---Secure_Game_Engine/actions/runs/44135186661/job/134222658936)
